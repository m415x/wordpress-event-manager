# WEM agent harness — compact operational cycle

This guide explains sequencing, not additional product rules. Follow [AGENTS.md](../AGENTS.md) for normative constraints, [testing.md](testing.md) for executable commands and environment isolation, Jira for acceptance and execution evidence, and GitHub for commits, PRs and CI.

1. **Bootstrap:** resolve current remote `dev` HEAD; read `AGENTS.md`, this index, relevant contracts and `docs/handoffs/current.md`. Fetch the *full* Jira issue, comments, blockers and relationships; check existing work before creating issues. Report authorized scope and pending decisions.
2. **Infrastructure decision:** before any local Docker/wp-env startup, inventory Compose projects, containers, networks, volumes, ports, active workloads and retained evidence (commands in `docs/testing.md`). Default to an already owned WEM environment with demonstrably isolated disposable test database/schema; keep manual WordPress strictly separate from PHPUnit. A branch/worktree alone never warrants a new stack. Prefer CI for repeatable unattended gates. Record why any exceptional instance is necessary (clean installation, migration, actual concurrency, backup restore, packaging or proven isolation incompatibility) and who owns it.
3. **Candidate:** create a bounded branch from verified `dev`. Record the target issue, intended contract and current candidate SHA. Avoid unrelated cleanup.
4. **TDD iteration:** demonstrate targeted expected assertion failure (RED), then the minimal fix and targeted GREEN. Keep separate Jira comments with actual SHA, command, observed output/reason, environment and evidence source per `AGENTS.md`. Environmental failures are ERROR, not RED. At each GREEN checkpoint link verified evidence, residual gates and the next approved step.
5. **Gate and PR:** run only relevant focused gates during development and the applicable full closure gates in `docs/testing.md`; reuse valid unchanged-SHA evidence. Verify PR HEAD and CI on that SHA. Record manual acceptance, limitations and packaged artifact digest where relevant; don't claim gates not observed.
6. **Integrate:** review bounded diff, merge authorized PR into `dev`, resolve merge SHA and post-merge CI. Distinguish candidate, PR HEAD, merge, and later documentation commits; never relabel old evidence as current-head proof.
7. **Reconcile:** update Jira status/evidence and `docs/handoffs/current.md` with implementation behavior, RED/GREEN pointers, actual SHAs, pending verification, blockers and next authorized action. Confirm remote `dev` again before declaring closure. A docs-only edit requires documentation review and applicable CI, not manufactured behavioral RED or repeated manual gates.

8. **Safe retirement:** after confirming no active jobs or pending evidence, stop only the specific inactive WEM services without destroying stored state. Before removing any resource, identify its Compose owner, exact container/network/volume names and dependencies, secure the evidence and obtain express authorization. Never modify other projects' Docker resources or run global prune/down-with-volumes commands. Record the disposition in Jira/handoff.

Classify unexpected findings and protect local artifacts using `AGENTS.md`. Do not reset a WordPress environment or delete ignored files to clear a gate without checking evidence and approval. The next agent should be able to continue using only current GitHub, Jira and durable documents.
